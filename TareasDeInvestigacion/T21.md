# T021 — Detección y anonimización MPC de rostros

## Estado

La integración local de YuNet con la anonimización MPC está implementada. El
cliente detecta rostros; las parties no ejecutan el detector. Al seleccionar el
modo de anonimización, el cliente convierte las cajas detectadas en la máscara
pública que MP-SPDZ aplica a los píxeles secretos. El resultado contiene cajas
negras dentro de las regiones preparadas. No se aplica blur.

La opción es explícita: el modo predeterminado continúa siendo `identity` y no
anonimiza. Para ocultar rostros se debe seleccionar `anonymize` y `--detect-faces`.

## Flujo implementado

1. La CLI carga una vez el modelo incluido en
   `src/client/preprocessing/face_detection_yunet_2023mar.onnx`, resolviendo la
   ruta desde el paquete y no desde el directorio actual.
2. `VideoPreprocessor` ejecuta YuNet sobre cada frame muestreado en BGR y a su
   resolución original. El umbral predeterminado del detector es 0.6 y el
   adaptador descarta detecciones con confianza menor o igual a 0.6.
3. Las cajas se escalan a las dimensiones reales del frame que se serializa,
   se redondean hacia fuera y se recortan a sus límites. Cada `FaceRegion`
   conserva el índice consecutivo del frame procesado y la confianza.
4. Antes de registrar el trabajo, la CLI convierte las regiones en resultados
   completos por frame, también para frames sin rostros, y prepara un
   `AnonymizationPlan`. Las coordenadas ya están en la resolución MPC; no se
   vuelven a reducir.
5. ExternalIO envía los píxeles originales como valores privados y la máscara
   binaria de posiciones como entrada pública. MP-SPDZ calcula
   `pixel * (1 - máscara)`: dentro de una caja el resultado es cero (negro), y
   fuera conserva el píxel original.
6. El cliente valida la salida MPC y reconstruye el video. No realiza el
   ocultamiento localmente ni cambia píxeles antes de enviarlos.

El contrato de cajas y coordenadas se describe en [T024](T24.md); el circuito,
el protocolo de máscara y sus límites están en [T025](T25.md). Las posiciones
de las regiones son públicas durante MPC y pueden revelar dónde aparecen
rostros.

## Comando de uso

Con las tres parties saludables y `MPC_PROGRAM=delta_video_anonymize`:

```bash
python -m client upload tests/video/video.mp4 --processing-mode anonymize --detect-faces
```

El archivo reconstruido queda en `output/<video_id>/reconstructed.mp4`. Para
ejecutar el cliente dentro de Compose:

```bash
docker compose up --build -d
docker compose run --rm delta-client upload /workspace/tests/video/video2.mp4 --processing-mode anonymize --detect-faces
```

Si se usa la CLI del host, el usuario debe poder leer
`.runtime/Player-Data/C0.key`. El setup de certificados en Docker puede crear
esa clave con otro propietario y permisos `600`; en ese caso se puede correr el
cliente en el contenedor o corregir el propietario de `C0.key` manteniendo
permisos privados.

## Cómo probar

### Pruebas rápidas, sin Docker ni parties

Instalar dependencias de desarrollo e instalar el paquete:

```bash
python -m pip install -r requirements-dev.txt
python -m pip install -e .
```

Las pruebas focalizadas de regiones faciales, umbral y conexión de CLI a MPC:

```bash
python -m pytest tests/unit/test_video_preprocessor.py tests/integration/test_plate_cli.py -k "face or point_six" -q
```

La prueba de preprocesamiento usa un YuNet doble determinista; la prueba de CLI
inyecta una `FaceRegion` y comprueba que llega al plan MPC y que la salida de
prueba deja en cero solamente los píxeles de esa caja. No depende de caras
encontradas en una imagen externa ni inicia los nodos.

Para la suite rápida completa:

```bash
python -m pytest -m "not e2e" -q
```

### Prueba MPC con tres parties reales

Desde `proyecto-delta/`, construir y levantar las parties:

```bash
docker compose up --build -d
docker compose ps
```

Con los servicios saludables, ejecutar el E2E existente de T025. Este utiliza
cajas sintéticas conocidas para comprobar contra MP-SPDZ que el interior se
vuelve negro y que los píxeles exteriores no cambian:

Linux/macOS:

```bash
RUN_MPC_E2E=1 python -m pytest tests/integration/test_mpc_anonymize_e2e.py -q -s
```

PowerShell:

```powershell
$env:RUN_MPC_E2E="1"
python -m pytest tests/integration/test_mpc_anonymize_e2e.py -q -s
```

Este E2E valida el circuito y ExternalIO con regiones controladas. La detección
real de YuNet y su conexión a MPC se valida además con la prueba de CLI
focalizada y una ejecución manual del comando `--detect-faces` sobre un video.

### Inspección de un video real

Ejecutar el comando de uso anterior y abrir el MP4 reconstruido. Confirmar que
las detecciones con confianza superior a 0.6 aparecen como rectángulos negros
en los frames procesados y que los píxeles fuera de esas cajas permanecen.
Revisar también frames con perfiles, rostros pequeños, oclusiones y poca luz:
YuNet puede omitir rostros y no se interpola una detección entre frames.

## Límites conocidos

- El umbral efectivo es estrictamente mayor que 0.6. `--conf-threshold` permite
  elevar el umbral que OpenCV aplica, pero el filtro del adaptador no permite
  bajar de 0.6.
- El detector analiza los frames seleccionados por el muestreo del video (hasta
  10 FPS por defecto), no necesariamente todos los frames originales.
- La detección usa el frame original a color; MPC recibe la representación
  grayscale y de resolución limitada configurada para el proyecto. Las cajas
  se mapean a ese tamaño antes de preparar la máscara.
- Una caja cubre el rectángulo detectado y no necesariamente todo el cabello,
  cuerpo u otras partes visibles de una persona. La calidad depende de YuNet y
  del umbral; no se garantiza que todos los rostros queden ocultos.
- El circuito existente solo implementa máscara negra. No implementa blur,
  seguimiento temporal ni relleno de detecciones omitidas.
- T025 reporta tiempos de MPC muy superiores a tiempo real en 640×480; la
  anonimización de videos largos puede tardar considerablemente.
