# T38 / T45 — Perfil ampliado y conteo local

## Funcionamiento

Se conserva el flujo: web → cliente Python → píxeles privados/máscaras públicas
→ tres parties MP-SPDZ → reconstrucción en el cliente Python. YuNet, LPD-YuNet
y YOLOX-S reciben el mismo muestreo original BGR antes de gris/resize.
YOLO solo cuenta; sus cajas no se agregan a las máscaras de anonimización.

- Perfil por defecto: hasta **30 FPS y 1920×1080**, sin ampliar ni deformar.
- No hay máximo fijo de duración ni de cuadros en web, APIs o circuito. La cota
  técnica del header es el entero con signo de 64 bits; no representa capacidad
  real. Se mantienen validación de longitud/bloques, padding, TLS y protocolo.
- Todo el video preprocesado sigue acumulándose en RAM. Un archivo largo puede
  agotar memoria/disco o tardar demasiado. Esto no implementa streaming.
- `DELTA_MAX_UPLOAD_MB` permite limitar el MP4 comprimido; vacío no fija máximo.
- YOLOX-S COCO (OpenCV Zoo, Apache 2.0) utiliza OpenCV CPU, sin PyTorch ni
  descargas durante ejecución. Modelo y SHA-256: `src/client/detection/models/README.md`.

## Conteo

`src/client/detection/yolo_counter.py` detecta `person` y `car` (no incluye
camiones, buses o motos). Asocia detecciones uno a uno por clase, solapamiento
y velocidad. Cada trayectoria suma **una vez**, al acumular tres observaciones;
tolera hasta 60 cuadros ausentes y elimina pistas caducadas.

No suma detecciones por frame. Dos carros simultáneos en posiciones distintas
generan dos trayectorias aunque tengan el mismo aspecto. Son conteos estimados:
cruces, oclusiones, errores del modelo o reapariciones después de caducar una
pista pueden omitir/duplicar objetos. No se implementa identificación biométrica
ni reidentificación garantizada entre escenas.

## Uso

Desde la raíz del repositorio:

```powershell
docker compose up --build -d --wait
# Otra terminal:
cd frontend
npm install
npm run dev
```

Compose levanta `client-api` en `http://127.0.0.1:8001`, además del Coordinator
y las parties. La web usa esa URL por defecto (`VITE_DELTA_CLIENT_URL`). No
levantar a la vez otro `uvicorn` en ese puerto. El original llega al cliente
Python de Docker; los modelos NO se ejecutan en JavaScript. Si Docker cambia
de computadora, ese original viajará a ella. No es todavía un despliegue público
con autenticación de servidor.

CLI con los tres modelos:

```powershell
python -m client upload "..\video3.mp4" --processing-mode anonymize --detect-faces --detect-plates --count-objects
```

Para pruebas económicas siguen disponibles `--mpc-fps 5 --mpc-max-width 128
--mpc-max-height 128`; no son el perfil predeterminado. `.env` es leído por
Compose, no automáticamente por la CLI Python del host.

La web muestra conteos, logs y descarga. CLI guarda `counts.json` junto al MP4;
la API conserva también `client.log` bajo `output/web/<job_web>/`. El progreso
ExternalIO es por bloques reales; sus tiempos incluyen Python y comunicación,
no son tiempos exclusivos del cálculo C++. El input temporal se borra al terminar.

## Verificación local

- 562 pruebas Python sin Docker; 73 pruebas TypeScript y build de producción.
- Nueve pruebas de interfaz en Edge, con fixture H.264 sintético reproducible.
- Cinco pruebas reales con tres parties: identidad anterior, dos de máscaras
  con regiones superpuestas/bloques entre cuadros, un cuadro 1080p y 21 s a 30 FPS
  en resolución mínima. Igualdad exacta donde corresponde antes del códec;
  interior negro/exterior intacto para anonimización; MP4 completo y cleanup.
- 1080p, **un cuadro** a 30 FPS: ExternalIO 123,750 s; flujo 131,294 s.
- 16×16, **630 cuadros / 21 s a 30 FPS**: ExternalIO 8,901 s; flujo 16,584 s.
- Brave real → API Docker → MPC → descarga: comienzo de video3 de **0,2 s,
  seis cuadros originales 478×850 a 30 FPS**, con rostros y placas ocultados.
  Conteo estimado: **1 persona, 2 carros**; ExternalIO por bloques **152,643 s**,
  recorrido web **180,920 s** (incluye login, detección, HTTP y descarga).
  Se decodificó la descarga: seis cuadros, mismo tamaño y FPS. La propia CLI
  verificó ceros interiores/igualdad exterior antes del MP4. Esta prueba no usa
  mocks de red ni sustitutos del cálculo MPC. Captura y resumen en
  `.runtime/T38_T45/browser-completed.png` y `browser-summary.json`.
- Inferencia YOLO real adicional sobre los tres primeros cuadros originales
  de video1, video2 y video3; los originales no se modificaron.

Estas pruebas son separadas: no demuestran viabilidad de videos largos Full HD
a 30 FPS. No se optimizó el cuello de botella de ExternalIO en esta tarea.
Los dos E2E antiguos de placas requieren recortes ignorados de T023 y se
omiten si no existen; la prueba web opt-in utiliza un comienzo de video3.

Comandos de regresión:

```powershell
python -m pytest -m "not e2e" -q
$env:RUN_MPC_E2E="1"
python -m pytest tests/integration/test_mpc_e2e.py tests/integration/test_mpc_anonymize_e2e.py tests/integration/test_extended_profile_e2e.py -q
# En frontend:
npm test -- --silent
npm run build
npm run test:e2e
```

`frontend/e2e/mpc-real.spec.ts` es opt-in con `RUN_WEB_MPC_E2E=1` y
`WEB_MPC_VIDEO_PATH` apuntando a un clip H.264 corto. `PLAYWRIGHT_BROWSER_PATH`
permite utilizar Brave en vez de Edge. No ejecutar esta prueba simultáneamente
con otra prueba MPC: solo se admite un trabajo activo. Evidencia local en
`.runtime/T38_T45/`. Los MP4V/FMP4 generados por OpenCV, incluido el video3
existente, pueden no previsualizarse en Chromium; la CLI sí los decodifica y
la descarga funciona. Los originales no se alteran para resolver esa limitación.
